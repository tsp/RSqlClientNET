Overview

This vignette compares reading and writing Microsoft SQL Server tables using RSqlClientNET, odbc, RODBCDBI, and RODBC. Its structure is inspired by the odbc benchmarks vignette, but these are new measurements, not the historical timings from that page.

The tables below display the values from benchmark-results.csv. Until you run the comparison, unmeasured values are shown as dashes rather than invented timings. You may edit the CSV directly or generate it with the accompanying script. The vignette can be built without a SQL Server or credentials.

The comparison measures elapsed wall-clock time, not just CPU time. Drivers must connect to the same SQL Server instance and database, from the same client machine. Connection setup, test-data generation, row-count verification, and cleanup are excluded from the timed sections.

Setup

To remain comparable with the original odbc vignette, we use nycflights13::flights, converted from tibble to data.frame, and omit the time_hour column. The data contain 336,776 rows and 18 columns after removal of that timestamp column.

flights <- as.data.frame(nycflights13::flights)
flights$time_hour <- NULL
stopifnot(ncol(flights) == 18L)

The runner connects to SQL Server with the existing RSqlClientNET connection string and an ODBC DSN. The examples below use Windows Authentication and the SqlClientRTest DSN; no username or password is stored in the repository. All drivers must reach the same SQL Server instance and database. RODBC and RODBCDBI are optional because their older interfaces have different capabilities and setup requirements.

library(DBI)

con_sqlclient <- DBI::dbConnect(
  RSqlClientNET::SqlClientNET(),
  connection_string = Sys.getenv("RSQLCLIENTNET_TEST_CONNECTION_STRING"),
  data_table = FALSE   # DBI-compatible data.frame result
)

con_odbc <- DBI::dbConnect(
  odbc::odbc(),
  dsn = Sys.getenv("RSQLCLIENTNET_BENCH_DSN", unset = "SqlClientRTest")
)

# Disconnect when finished:
DBI::dbDisconnect(con_sqlclient)
DBI::dbDisconnect(con_odbc)

Writing

Each driver uploads the same flights data to a new, driver-specific table. The write timer includes table creation and data upload, using dbWriteTable() for the DBI drivers and RODBC::sqlSave() for RODBC. The table is checked and deleted after the timer has stopped. Repetitions run in randomized order to reduce systematic warm-up effects. A single manually timed write would look like this (the accompanying runner repeats and verifies it automatically):

write_time <- system.time(
  DBI::dbWriteTable(con_sqlclient, "rscn_bench_write", flights,
                    row.names = FALSE)
)[["elapsed"]]
DBI::dbRemoveTable(con_sqlclient, "rscn_bench_write")

Reading

A single common flights table is populated with RSqlClientNET before measurement. Each backend reads that same table using dbReadTable() or RODBC::sqlFetch(). The elapsed time includes fetching and materializing an R result, but not preparing the SQL table. Each result is checked for the expected number of rows and columns.

# Set up a common table once, before timing any reads:
DBI::dbWriteTable(con_sqlclient, "rscn_bench_read", flights,
                  row.names = FALSE)
read_time <- system.time(
  result <- DBI::dbReadTable(con_odbc, "rscn_bench_read")
)[["elapsed"]]
stopifnot(nrow(result) == nrow(flights))
DBI::dbRemoveTable(con_sqlclient, "rscn_bench_read")

Speed vs. odbc is computed as odbc elapsed / driver elapsed; values above 1.00× indicate faster execution than odbc for that operation and setup. Blank values mean no result has been entered. The comparison does not imply that one driver will be faster across all SQL types or workloads.

Enter your results

Edit vignettes/benchmark-results.csv and replace the empty seconds values with your measured median elapsed times. Fill in n_rows and repetitions if available. Do not enter numbers from the historical odbc webpage, since they were measured on a different system and with different software versions.

Alternatively, from the project root run:

# `con_str` is your existing trusted Windows Authentication connection string.
Sys.setenv(
  RSQLCLIENTNET_TEST_CONNECTION_STRING = con_str,
  RSQLCLIENTNET_BENCH_DSN = "SqlClientRTest",
  RSQLCLIENTNET_BENCH_EXTRA_DRIVERS = "RODBCDBI,RODBC",
  RSQLCLIENTNET_VIGNETTE_REPEATS = 5
)
# Clear optional connection-string overrides so the runner uses the DSN.
Sys.unsetenv(c("ODBC_CONNECTION_STRING", "RSQLCLIENTNET_BENCH_ODBC_CONNECTION_STRING"))
source("tools/benchmarks/flights-vignette-benchmark.R")
result <- run_flights_vignette_benchmark()

# Rebuild the HTML vignette after collecting results:
rmarkdown::render("vignettes/benchmarks.Rmd", quiet = TRUE)

The runner defaults to three repetitions and compares RSqlClientNET and odbc; the example above requests five repetitions and includes the optional RODBC / RODBCDBI drivers using the same DSN. It overwrites the CSV template with the newly measured medians, and prints all attempts in the console. To inspect variability, increase the repetition count or retain the per-attempt CSV written alongside the medians.

Interpretation and reproducibility

Benchmarks are highly sensitive to operating system, R version, driver version, network latency, SQL Server configuration, SQL table types, and caching. Report these alongside the timings. In particular:

  • RSqlClientNET uses its default native columnar read transport and default read batch size (32,768 rows in v0.1.0).
  • All DBI drivers return an ordinary data.frame for this benchmark; RSqlClientNET’s optional data_table = TRUE is not enabled.
  • The timestamp column is excluded to match the published odbc vignette. For performance involving SQL Server datetime / datetime2 and timezones, use the separate tools/benchmarks/datetime-local-binary.R benchmark.
  • These operations use SQL Server tables, not R-only serialization or local synthetic data frames; connection establishment and test data setup are outside the timers.
  • RODBC and RODBCDBI have older APIs and may be unavailable or reject particular data types. Missing measurements should remain blank rather than being treated as zero.

Source and methodology: odbc benchmarks. This vignette is maintained as part of RSqlClientNET; it does not incorporate timing claims from that earlier benchmark.

Bulk insert, TableLock and SQL Server transaction logging

dbWriteTable() and dbAppendTable() support an explicit table_lock = TRUE argument, which maps to SqlBulkCopyOptions.TableLock for that operation only (FALSE by default). Locking can reduce performance in concurrent systems, so it is intentionally opt-in. SQL Server can use minimal logging for eligible bulk operations under SIMPLE/BULK_LOGGED recovery, subject to table/index structure and additional engine conditions. Do not assume this applies to indexed tables or databases using FULL recovery.

In an October 2026 developer test (SQL Server 2025 Express, SIMPLE, empty disposable VARCHAR(MAX) heap), the median elapsed time for 50,000 values was 9.33 s with table_lock = FALSE, 5.61 s with table_lock = TRUE, and 13.45 s for standard odbc append (five repeats). Logically generated transaction log bytes were about 140 MB and 5.38 MB respectively for the RSqlClientNET alternatives. These measurements are workload-specific and should not be generalized to production.

For reproducible comparisons of SQL transaction behavior, use tools/benchmarks/benchmark-bulk-transactions.R. The result$logical_log values come from separately instrumented writes with an explicit DBI transaction, read before commit. Physical file I/O is database-wide rather than per-transaction; sums of wait times may include parallel workers. tools/benchmarks/benchmark-create-vs-append.R independently compares creation and append workflows, including a precreated indexed table. Tests must run only on disposable databases.
